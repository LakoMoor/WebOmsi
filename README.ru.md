# WebOmsi

**Автобусный симулятор, который работает прямо в браузере.**<br>
Мультиплеер, сенсорное управление для телефонов, ничего не нужно устанавливать.

[**▶ Играть**](https://lakomoor.github.io/WebOmsi/) &nbsp;·&nbsp; [English](README.md) &nbsp;·&nbsp; [Документация движка](https://lakomoor.github.io/WebOmsi/engine/)

<img src="docs/webomsi/cab.png" width="820" alt="Вид из кабины городского автобуса">

</div>

WebOmsi — форк [openOMSI](https://github.com/openOMSI-Project/openOMSI), переписанного на Rust симулятора OMSI 2,
доведённый до запуска на веб-странице. Симуляция, рендерер, движок скриптов и сетевой протокол остались движковыми;
новое здесь всё, что позволяет им жить в браузере, и небольшая оригинальная игра, в которую можно играть сразу.

## Играть

Откройте **<https://lakomoor.github.io/WebOmsi/>** в Chrome или Edge (на телефоне — Chrome для Android), выберите
автобус и нажмите **Играть**. При первом запуске скачивается движок (около 23 МБ, 7 МБ в сжатом виде); контент
демо-игры весит 160 КБ. И то и другое браузер запоминает.

| | |
|---|---|
| <img src="docs/webomsi/menu.png" alt="Стартовый экран"> | <img src="docs/webomsi/touch.png" alt="Сенсорное управление"> |
| Стартовый экран на русском и английском, карточки автобусов, пресеты графики | Руль, педали, коробка передач, двери, поворотники и гудок на экране |

**Нужен** браузер с [WebGPU](https://caniuse.com/webgpu): Chrome или Edge 113+ на компьютере, Chrome на Android.
Safari и Firefox пока не поддерживаются.

### Управление

| Клавиатура | |
|---|---|
| `W` / `S` | газ / тормоз |
| `A` / `D` | руль |
| `Space` | стояночный тормоз |
| `Shift+U` | запустить автобус (стоковые автобусы OMSI) |
| `Shift+1` … | открыть и закрыть двери |
| `H` | гудок |
| `Z` `X` `C` | поворотники, аварийка |
| `F1` … | камеры (кабина, снаружи, салон) |
| `Esc` | меню игры |

На сенсорном экране игра рисует свои органы управления: руль слева, **BRAKE** и **GAS** справа, кнопки коробки передач
(**R N D**), дверей, поворотников, гудка и стояночного тормоза (**P**). Палец по экрану — осмотреться, щипок — приблизить.
Поверните телефон горизонтально; страница сама просит полный экран.

## Демо-игра

На опубликованной странице играют в небольшую игру, оригинальную от первого байта: деревня **Demo** (петля дороги, дома,
деревья, остановка) и четыре автобуса. Ничего из OMSI 2 или другой игры в ней нет: каждая текстура, модель, файл карты и
скрипт генерируется кодом [`tools/public`](tools/public) и передан в общественное достояние
([CC0](https://creativecommons.org/publicdomain/zero/1.0/deed.ru)).

| Городской | Микроавтобус | Длинный |
|---|---|---|
| <img src="docs/webomsi/cab.png"> | <img src="docs/webomsi/mini.png"> | <img src="docs/webomsi/long.png"> |
| 10,6 м, 170 кВт | 7,4 м, 110 кВт | 12,2 м, 210 кВт |

Есть и двухэтажный автобус (10,4 м, 190 кВт) с сиденьями на обеих палубах.

Автобусы сделаны на настоящих файлах OMSI (`.bus`, конфиг модели, меши `.o3d`, скрипты `.osc`), так что демо ещё и
небольшой пример форматов. Пересобрать: `tools/public/build.sh`; поменяйте число в
[`gen_bus.py`](tools/public/gen_bus.py) — получится другой автобус.

## Мультиплеер

<img src="docs/webomsi/multiplayer.png" width="560" align="right" alt="Два браузера в одной игре">

Играть вместе можно тремя способами, все в разделе **Мультиплеер** на стартовом экране:

* **Публичный список**: открытые сейчас комнаты и серверы, войти одним нажатием.
* **Комната в браузере**: нажмите *Создать комнату* и отправьте друзьям код или ссылку-приглашение. **Ни сервера, ни
  установки**: ваш браузер и есть сервер, их браузеры подключаются к нему напрямую (WebRTC). Отметьте *Показывать мою
  комнату в публичном списке*, чтобы её находили незнакомцы.
* **Выделенный сервер** для постоянного места: `docker compose -f deploy/docker-compose.yml up -d` на любой машине с
  доменом или на своём компьютере через бесплатный туннель. [`deploy/announce.sh`](deploy/announce.sh) выставляет его в
  публичный список.

Все видят автобусы, имена и чат друг друга. Список составляют сами хосты, он не проверяется.
**[Пошаговая инструкция →](docs/webomsi/multiplayer.ru.md)** (вход, хостинг, свой сервер, если не подключается)

## Свои файлы

На стартовом экране есть раздел **Свои файлы**: перетащите zip с картой, автобусом, объектами или целой папкой OMSI, и
они будут играть вместе со встроенной игрой. Страница читает каждый архив и показывает найденные карты и автобусы;
файлы остаются в собственном хранилище браузера и никуда не загружаются.

<img src="docs/webomsi/menu-phone.png" width="260" align="right" alt="Стартовый экран на телефоне">

* мод **в том виде, как вы его скачали**, работает без изменений, в том числе внутри обёртки вроде `OMSI 2/Vehicles/...`;
* игра видит все ваши zip как одну папку, поэтому zip карты и zip автобуса могут быть отдельными файлами;
* автобусу, который берёт скрипты или текстуры другого дополнения, нужно и это дополнение в zip.

[**Пошаговая инструкция →**](docs/webomsi/own-content.ru.md) (что может быть в zip, как вырезать небольшой zip из своего OMSI 2
скриптом [`tools/pack/make_pack.py`](tools/pack/make_pack.py), ограничения по размеру, что значат сообщения консоли).

Файлы OMSI 2 и большинство модов нам не принадлежат, поэтому в этот сайт они никогда не входят: добавляйте только то,
что вам можно использовать, и не публикуйте файлы OMSI 2. WebOmsi не связан с авторами OMSI 2.

## Сборка самостоятельно

Нужны [Rust](https://rustup.rs) (тулчейн `1.97.1`: `rustup toolchain install 1.97.1`), его WebAssembly-таргет,
`wasm-bindgen` и Python 3.

```sh
rustup target add wasm32-unknown-unknown --toolchain 1.97.1
cargo +1.97.1 install wasm-bindgen-cli --version 0.2.128 --locked

tools/public/build.sh          # демо-контент -> web/demo-pack.zip
./build-web.sh                 # игра для браузера -> web/pkg   (около 6 минут)
cd web && python3 -m http.server 8080
```

Откройте <http://localhost:8080>. `?touch=1` покажет сенсорное управление на компьютере, `?server=wss://…/ws` подключит к
серверу, `?quality=low` включит лёгкую графику.

**Опубликовать свою копию** можно за три шага: сделайте форк, в *Settings → Pages → Source* выберите *GitHub Actions*,
запушьте в `main`. [`pages.yml`](.github/workflows/pages.yml) соберёт игру и демо-контент и опубликует страницу на
`https://<вы>.github.io/<репозиторий>/`.

## Как это устроено

Веб-версия — набор изменений движка, ни одно из которых не меняет работу настольной игры:

| Проблема в браузере | Что делает WebOmsi |
|---|---|
| Нет файловой системы | Файлы игры — один zip в памяти, смонтированный как папка (`omsi_cfg::vfs::mount_zip_memory`). |
| Настройка GPU асинхронна | `web::start` сначала открывает устройство WebGPU, затем запускает цикл событий winit на канвасе страницы. |
| Нет потоков | Загрузка тайлов, расчёт неба и работа с текстурами идут на месте; пулы rayon используют единственный поток страницы. |
| Нет UDP | `omsi_net::Socket` — UDP на компьютере, WebSocket или каналы данных WebRTC на странице; код сессии не менялся. |
| Нет аудиоустройства | Web Audio через cpal. |
| Строгий WGSL в Chrome | Шейдеры проверяет Tint; производные в неоднородном потоке разрешены явно. |
| `Instant`, id процесса, сон | `web-time`, `omsi_cfg::pid()`, `omsi_cfg::sleep()`. |
| Зависимости только для ПК (плагины, обновления, буфер обмена, диалоги) | Крейты-заменители и `cfg(target_arch = "wasm32")`; лаунчер компилируется, но не используется. |

Движок, крейты и документация форматов ([docs/FORMATS.md](docs/FORMATS.md)) — upstream.

## Известные ограничения

* Один поток: загрузка карты занимает несколько секунд, страница в это время не отвечает.
* Первый кадр компилирует шейдеры; на некоторых системах компилятор шейдеров Chrome под нагрузкой падает, и игра
  переходит на рендер без мультисэмплинга.
* В демо нет ИИ-трафика и пассажиров; движок поддерживает их для карт, где они заданы.
* Плагины (Lua и DLL), Discord, Steam, VR и лаунчер — только на ПК.
